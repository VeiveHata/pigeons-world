## Project

"DoToDo" / Pigeons World: a client-only study tracker (Vue 3 + Vue Router + Vite + Tailwind 3, TypeScript). Study sessions reveal tiles of a pigeon picture and grow a plant per topic; grown plants go into a garden on the home page. There is no backend: all state lives in `localStorage`, with a JSON backup file as the only way to move or restore it.

`README.md` is the detailed spec of user-facing behavior (timer, music, notes, backup/merge rules, garden, stats, tiles, theme). Read the relevant section before changing a feature, and update it when behavior changes — commits normally change README alongside code.

## Commands

```shell
npm run dev            # Vite dev server on :5173 (npm start also opens the browser)
npm run build          # vue-tsc --noEmit, then vite build to dist/
npm run build.types    # type-check only
npm run lint           # ESLint on src/**/*.{ts,vue}
npm run fmt.check      # Prettier check (npm run fmt to write)
npm run tiles          # slice assets-src images into public/tiles + regenerate src/pictures/tile-map.json
npm run plants         # redraw placeholder plant SVGs in public/plants/ from src/theme/colors.js
```

There is no test suite. Verify with `npm run build` and `npm run lint`, and by running the app. Dev-only URL flags (ignored in production, defined in `src/tracker/config.ts`):
- `?minutes=0.1` — make a session last 6 seconds.
- `?test-plant` (on `/`) — add a fully grown "Test topic" waiting under Ready to plant.
- `samples/grown-plant.json` can be loaded via the backup dialog (Merge) to get a grown plant.

## Architecture

**Global state is a module-level singleton, not a store library.** `src/tracker/useTracker.ts` creates one `reactive` state at import time, loads it from `localStorage` key `pigeons-world.tracker.v1`, and deep-watches it to save on every change. A single 250 ms `setInterval` `tick()` drives every timer and also finishes sessions that ended while the page was closed. `useTracker()` just exposes computed views and mutation functions over that shared state. Other composables (`useFocusMusic`, `useBackup`) follow the same module-singleton pattern and import from `useTracker`.

**Saved data must stay backward compatible.** `normalize()` in `useTracker.ts` upgrades any older save (missing plants, levels, notes, pictures, garden, sessions; revealed squares stored as grid indexes) to the current `State`. When adding a field to `Topic`/`State`:
1. Make it optional in `SavedState` and default it in `normalize()`.
2. Handle it in `src/backup/backup.ts`: validation/cleanup on import (`readBackupFile`), and a merge rule in `mergeBackup` (merge never deletes; same file twice must be a no-op). Bump `FORMAT_VERSION` only if the file shape changes incompatibly; older versions must still import.
3. Describe it in the README's backup section.

**Pictures are addressed by tile id, never by grid position.** `src/pictures/pictures.json` (hand-edited) defines pictures; `tile-map.json` is generated by `scripts/slice-image.mjs` and must not be edited. Tile ids are deterministic from image + settings, so re-running `npm run tiles` keeps saved progress valid, but changing a picture's image/grid/crop invalidates it. The full source image in `assets-src/` is never served. Topics store `pictureId` + revealed tile ids; `tileIdsFromLegacy` converts old index-based saves.

**Domain modules are plain TS, components are thin.** Logic lives in `src/{tracker,backup,garden,plants,pictures,stats,notes,music}/*.ts`; `src/components/<area>/` and `src/pages/` render it. Routes and their `meta.title`/`meta.description` are in `src/router.ts` (applied to the document in `afterEach`). `App.vue` mounts `useFocusMusic()` once so music follows the running timer across all pages.

**Theme colours have one source of truth:** `src/theme/colors.js`. `tailwind.config.js` replaces Tailwind's default palette with these, exposing each as a CSS variable (`--color-navy`, RGB triplet) and a Tailwind colour (so `bg-navy/40` works). In CSS use `rgb(var(--color-x))`; in JS needing a string use `themeColor()` from `src/theme/theme.ts`. A custom Vite plugin restarts the dev server when `colors.js` or `tailwind.config.js` changes. `index.html` (`theme-color`) and `public/manifest.json` hold literal copies of navy/pale green that must be updated by hand. Fonts: `font-typewriter` (Courier Prime, default) and `font-display` (Special Elite, headings), bundled via Fontsource.

**Music** (`src/music/`): track list in `music.ts`, files in `public/music/<title-lowercase-dashed>.m4a`. Every track needs a credit/licence shown in the player; only free-to-use music is allowed (see README Credits).

## Conventions

- Path alias `@/` → `src/`.
- Code comments explain *why* in plain sentences (often user-facing behavior); keep that style.
- `localStorage` access is always wrapped in try/catch and degrades silently.
- The router uses HTML5 history mode; static hosts need an SPA fallback to `index.html`.
